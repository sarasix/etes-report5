02 / METHOD

เลือกก่อนเห็นคำถาม เก็บไว้ใช้ตอบหลายข้อ

01

สร้าง candidate ประมาณ 1 fps
ใช้เฟรมตามเวลาเป็นตัวเลือกก่อนลดเหลือสูงสุด 16 เฟรม

02

หาเหตุการณ์สองประเภท
Subtitle event คือจุดเริ่มหรือข้อความเปลี่ยน ส่วน scene event คือจุดสูงสุดเฉพาะที่ของค่าความเปลี่ยนแปลงภาพ

03

ให้น้ำหนักรวมแต่ละประเภทเท่ากัน
ถ้ามี subtitle 4 events แต่ละจุดได้ 1/4 และ scene 20 events แต่ละจุดได้ 1/20

04

เลือกทีละเฟรม แล้วเรียงตามเวลา
คะแนน event มากสุดก่อน ถ้าเสมอใช้ระยะห่างใกล้สุดจากชุดเดิม จากนั้น scene strength และเวลาที่มาก่อน

ทำไมมีเลข 1?

w(e) = 1 / Nm

1 / N: น้ำหนักหนึ่งหน่วย แบ่งให้ event ของประเภท m ทั้งหมด จึงไม่ให้ประเภทที่มี event มากกว่าชนะเพียงเพราะจำนวนมาก

Δ(t | S) = Σe∈E(t) w(e) · 𝟙[e∉Cov(S)]

𝟙[เงื่อนไข]: ได้ 1 เมื่อ event ยังไม่ถูกเก็บ และ 0 เมื่อถูกเก็บแล้ว ตัวนี้เป็น indicator ไม่ใช่ probability

หากประเภทใดไม่มี event จะไม่ให้น้ำหนักประเภทนั้นและไม่หารด้วยศูนย์ การให้น้ำหนักรวมเท่ากันเป็นสมมติฐานของวิธี ไม่ใช่ค่าน้ำหนักที่เรียนรู้

ต้นทุนที่รายงาน

Report 5 ระบุเวลา inference เฉลี่ย 8.39 วินาที/คำถาม และจำนวนเฟรมเฉลี่ย 14.9 เฟรม/วิดีโอ ใน evidence stores

ตัวเลขเวลาไม่รวมเป็นหลักฐานว่าทั้งระบบเร็วขึ้นเท่าใด ต้องรวมเวลา decode, ตรวจ event, เลือกเฟรม และ inference ภายใต้เงื่อนไขเดียวกัน

คลิปสั้นที่มี candidate ไม่เกิน 16 จะเลือกทั้งหมด จึงไม่ได้ลดเฟรมลงครึ่งหนึ่งทุกคลิป

รายละเอียด scene peak จาก implementation

ใช้ค่าความต่าง HSV histogram ระหว่าง candidate กำหนด threshold ของคลิปเป็น median + MAD เลือกจุดที่ไม่น้อยกว่า threshold และค่าก่อนหน้า แต่สูงกว่าค่าถัดไป วิธีนี้เป็น heuristic ตรวจการเปลี่ยนภาพ ไม่รับรองว่าเป็นขอบเขตฉากเชิงความหมายทุกจุด

ขอบเขตของ coverage ในโค้ดปัจจุบัน

แต่ละ event ผูกกับ candidate เดียว ไม่มีหน้าต่างเวลาที่ให้หลายเฟรมแทน event เดียวกัน ดังนั้นการบันทึก covered event ไม่ลดคะแนนของ candidate อื่น วิธีปัจจุบันจึงใกล้กับการจัดอันดับ event credit พร้อม temporal tie-break มากกว่าการครอบคลุมช่วงเวลาแบบทับซ้อน

เมื่อคะแนน event เหลือศูนย์ทุกตัว จะเลือกต่อด้วยระยะห่าง ตามด้วย scene strength และเวลา โดยไม่บังคับเก็บต้นหรือท้ายคลิป

ข้อจำกัดและการทดลองต่อไป

ผลนี้เป็น validation หนึ่งโมเดล ยังไม่ยืนยันความสามารถข้ามโมเดลหรือข้อมูลใหม่ ควรเทียบคำตอบรายข้อพร้อมช่วงความเชื่อมั่นที่คำนึงถึงหลายคำถามต่อวิดีโอ และทำ ablation แยก scene / subtitle / fusion รวมถึงเวลา end-to-end
